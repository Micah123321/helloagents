# ~idea 命令 - 轻量探索

直接执行类命令，用于轻量探索和方向比较，不写文件，不修改代码。

---

## 执行规则

```yaml
命令: ~idea [<主题描述>]
类型: 直接执行类
触发: ~idea
功能: 探索思路、比较方向、分析可行性，纯分析输出
评估: 无评估
说明: 原子操作，无状态变量设置，不创建方案包，不修改任何文件
```

---

## 执行模式适配

```yaml
规则:
  1. 独立工具命令，不受 WORKFLOW_MODE 影响
  2. 只读操作，不写文件，不修改代码
  3. 输出为分析结论，不进入任何执行阶段
  4. 可结合项目上下文和外部搜索增强分析
```

---

## 执行流程

### 步骤1: 理解探索主题

```yaml
解析用户输入:
  有主题: 提取探索方向和关键问题
  无主题: 输出: 错误（请提供探索主题），流程结束

上下文收集（只读，不创建知识库）:
  已有项目: 读取项目配置/结构/知识库摘要，理解技术栈和约束
  无项目上下文: 基于主题独立分析
```

### 步骤2: 多方向分析

```yaml
分析维度（按主题性质选择相关维度）:
  技术可行性: 各方向的实现难度、技术栈适配度、依赖复杂度
  方案对比: 2~4 个方向的优缺点对比（表格形式）
  风险评估: 各方向的潜在风险和不确定性
  生态与趋势: 社区活跃度、维护状态、发展方向
  适配评估: 与项目现有架构/技术栈的兼容性

外部搜索（按需）:
  主题涉及具体技术/库/框架 → 查询最新文档和社区评价
  主题涉及最佳实践 → 搜索当前主流方案
```

### 步骤3: 输出探索结论

```yaml
输出格式:
  状态栏: 💡【HelloAGENTS】- 探索：{主题简称}
  主体:
    - 方向概览（各方向 1~2 句话总结）
    - 对比分析（表格：方向 × 维度）
    - 推荐方向 + 推荐理由
    - 后续建议（如需深入可用 ~plan 或 ~auto）
  下一步引导: 引导用户选择方向后使用 ~plan 或 ~auto 推进

输出: 完成（探索分析结论）
→ 状态重置
```

---

## 不确定性处理

| 场景 | 处理 |
|------|------|
| 主题过于宽泛 | 拆分为 2~3 个子主题分别分析 |
| 主题超出技术领域 | 按通用分析框架处理 |
| 信息不足无法对比 | 标注信息缺口，建议用户补充 |
| 方向间无显著差异 | 明确说明各方向等价，推荐最简方案 |

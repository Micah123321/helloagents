# ~build 命令 - 快速实现

本模块定义快速实现命令的规则。~build 是 ~exec 的超集：有方案包时执行方案包，无方案包时按用户请求走 R1/R2 流程实现。

---

## 命令说明

```yaml
命令: ~build [<需求描述>]
类型: 完整流程类
功能: 按当前请求或现有方案实现
目标模式: 由路径分支决定（有方案包→DIRECT，无方案包→R1/R2 级别判定决定模式）
```

**DO:** 先检测方案包，再决定路径

**DO NOT:** 跳过方案包检测直接进入需求评估，用户确认前设置 WORKFLOW_MODE

---

## 执行模式适配

```yaml
规则:
  1. 优先检测已有方案包，有则执行
  2. 无方案包时按需求描述走路由判定（R1/R2）
  3. 两条路径共用相同的完成/状态重置逻辑
```

---

## 执行流程

### 步骤1: 方案包检测

```yaml
前置迁移: [→ services/knowledge.md 前置检查 步骤2]

扫描 {KB_ROOT}/plan/ 目录:
  有方案包 → 路径A（执行方案包）
  无方案包 或 plan/ 不存在 → 路径B（按需求实现）
```

### 路径A: 执行方案包（等价 ~exec）

```yaml
设置: STAGE_ENTRY_MODE = DIRECT, WORKFLOW_MODE = INTERACTIVE

1个方案包 或 命令指定名称匹配:
  输出: 确认（方案包名称+类型+任务数）
  ⛔ END_TURN
  用户确认后:
    继续: 设置 CURRENT_PACKAGE → 验证完整性 → 步骤3
    切换到路径B: 忽略方案包，按需求实现
    取消: → 状态重置

多个方案包（未指定）:
  输出: 确认（方案包选择清单 + "或忽略方案包直接实现"选项）
  ⛔ END_TURN
  用户选择后:
    选择方案包N: 设置 CURRENT_PACKAGE → 验证完整性 → 步骤3
    直接实现: → 路径B
    取消: → 状态重置

验证方案包完整性:
  检查: proposal.md（存在且非空）+ tasks.md（至少1个任务项）
  失败: 输出: 警告（完整性问题），提供修复/忽略/取消选项

检查方案包类型:
  implementation: → 步骤3
  overview: → Overview 类型处理 [→ services/package.md]
```

### 路径B: 按需求实现（走路由判定）

```yaml
无需求描述: 输出: 错误（请提供需求描述或创建方案包），流程结束

有需求描述:
  按 G4 通用路径级别判定（5 个维度评估）:

  R1 级别:
    设置: STAGE_ENTRY_MODE = NATURAL
    按 G4 R1 快速流程执行（EHRB→定位→修改→KB同步→验收）
    → 状态重置

  R2 级别:
    设置: STAGE_ENTRY_MODE = NATURAL
    按 G4 R2 标准流程:
      需求评估（评分+追问+EHRB）→ 确认 → ⛔ END_TURN
      用户确认后:
        委托执行: WORKFLOW_MODE = DELEGATED → 阶段链
        交互式执行: WORKFLOW_MODE = INTERACTIVE → 阶段链
        改需求: 回到评估
        取消: → 状态重置

    阶段链:
      1. DESIGN（方案设计）
      2. DEVELOP（开发实施）
      3. 验收 + 完成 → 状态重置
```

### 步骤3: 开发实施（路径A）

```yaml
按 G7 按需读取表"R2 进入开发实施（入口）"加载
```

### 步骤4: 后续操作

```yaml
验收: 按 G8 流程级验收规则执行
遗留方案包扫描 [→ services/package.md scan()]
输出: 完成（验收报告+变更摘要）
→ 状态重置
```

---

## 不确定性处理

| 场景 | 处理 |
|------|------|
| 无方案包且无需求描述 | 输出: 错误，提示提供需求或先 ~plan |
| 方案包验证失败 | 提供修复/忽略/取消选项 |
| 路径B 需求模糊 | 按 G4 R2 评估流程追问 |
| 路径A 执行中发现需升级 | 按 G4 R1→R2 升级判定 |

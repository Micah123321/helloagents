# ~wiki 命令 - 知识库管理

本模块定义纯知识库创建和同步的执行规则。~wiki 是 ~init 的知识库子集，仅处理知识库操作，不处理项目级规则文件和 skills 链接。

---

## 命令说明

```yaml
命令: ~wiki [<操作>]
类型: 场景确认类
功能: 只创建或同步项目知识库
评估: 需求理解 + EHRB 检测（不评分不追问）
```

---

## 执行模式适配

```yaml
规则:
  1. 独立工具命令，不受 WORKFLOW_MODE 影响
  2. KB_CREATE_MODE=0 时需用户确认后执行
  3. 支持创建和同步两种操作
  4. 大型项目启用分批处理
```

---

## 执行流程

### 步骤1: 需求理解 + EHRB 检测

```yaml
无独立输出，直接进入下一步
```

### 步骤2: 检测知识库状态

```yaml
知识库开关检查:
  KB_CREATE_MODE=0: 输出: 确认（开关状态）
    ⛔ END_TURN
    用户确认后:
      继续: 继续下方流程
      取消: → 状态重置
  KB_CREATE_MODE=1/2/3: 直接继续

旧目录名迁移检测: [→ services/knowledge.md 前置检查 步骤2]

知识库状态:
  不存在 → 路径A（创建）
  存在 → 路径B（同步）

用户明确指定操作时:
  ~wiki create / ~wiki 创建 → 路径A
  ~wiki sync / ~wiki 同步 → 路径B（知识库不存在时提示先创建）
```

### 路径A: 创建知识库

```yaml
扫描代码库:
  优先: 根目录配置文件（package.json/pyproject.toml/Cargo.toml 等）
  按需: 目录结构和源代码文件
  并行读取: 多个配置文件同时读取

技术栈识别 + 模块结构提取

创建:
  目录结构: 按 G1 知识库完整结构创建
  模板: 读取 services/templates.md
  ≥2个模块目录: 按编排五步法调度子代理并行扫描 [→ G10]
  仅1个模块目录: 主代理直接扫描

.gitignore 检查: [→ functions/init.md 步骤3 .gitignore 检查]

输出: 确认（知识库创建预览）
⛔ END_TURN
用户确认后: 创建 / 取消(→状态重置)
```

### 路径B: 同步知识库

```yaml
对比分析:
  1. 读取现有知识库内容（INDEX.md、context.md、modules/）
  2. 扫描当前代码库状态
  3. 对比差异:
     - 新增模块（代码中有，知识库中无）
     - 过时模块（知识库中有，代码中已删除）
     - 内容变更（模块接口/结构已变但文档未更新）

无差异: 输出: 完成（知识库已是最新），流程结束

有差异:
  输出: 确认（差异列表+同步计划）
  ⛔ END_TURN
  用户确认后:
    全部同步: 更新所有差异项
    选择性同步: 用户选择要更新的项
    取消: → 状态重置

执行同步:
  新增: 创建 modules/{模块名}.md
  过时: 标注为"已废弃"或删除（用户选择）
  变更: 更新模块文档内容
  更新: CHANGELOG.md 记录同步操作
```

### 步骤3: 后续操作

```yaml
验收:
  完整性: 核心文件存在且非空，模块覆盖完整
  安全性: 无敏感信息泄露

输出: 完成（创建/同步结果）
→ 状态重置
```

---

## 不确定性处理

| 场景 | 处理 |
|------|------|
| 空项目（无源代码） | 输出: 错误，建议确认目录 |
| 无法识别项目类型 | 询问用户提供技术栈信息 |
| 同步冲突（手动编辑过） | 展示差异，让用户决定保留/覆盖 |
| 模块数量过多 | 分批处理，优先核心模块 |

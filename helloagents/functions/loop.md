# ~loop 命令 - 循环改进

本模块定义设置指标和守卫命令，循环改进、保留或回滚的执行规则。

---

## 命令说明

```yaml
命令: ~loop [<指标描述>]
类型: 场景确认类
功能: 设置质量指标和守卫命令，循环执行改进直到指标达标或用户中止
评估: 需求理解 + EHRB 检测（不评分不追问）
```

---

## 执行模式适配

```yaml
规则:
  1. 独立工具命令，不受 WORKFLOW_MODE 影响
  2. 每轮改进后运行守卫命令验证指标
  3. 指标未达标时自动尝试下一轮改进（最多 N 轮）
  4. 每轮改进可独立回滚
```

---

## 执行流程

### 步骤1: 需求理解 + EHRB 检测

```yaml
无独立输出，直接进入下一步
```

### 步骤2: 设置指标和守卫命令

```yaml
解析用户输入:
  有指标描述: 提取指标名称、目标值、守卫命令
  无指标描述: 交互式设置

交互式设置:
  输出: 确认（指标设置）
  ⛔ END_TURN

  用户需提供:
    指标名称: 要改进的目标（如测试覆盖率、lint 错误数、构建时间、包体积）
    目标值: 达标条件（如 ≥80%、=0、<5s、<500KB）
    守卫命令: 验证指标的命令（如 pytest --cov、eslint .、npm run build）
    最大轮次: 循环上限（默认 5 轮）

  自动检测（项目上下文可推断时）:
    读取项目配置推荐指标和守卫命令
    用户确认或调整

确认指标设置:
  输出: 确认（指标+目标值+守卫命令+最大轮次）
  ⛔ END_TURN
  用户确认后: 继续 / 调整 / 取消(→状态重置)
```

### 步骤3: 基线测量

```yaml
执行守卫命令 → 记录当前指标值（基线）

基线已达标: 输出: 完成（指标已达标，无需改进），流程结束
基线未达标: 记录差距 → 进入改进循环
```

### 步骤4: 改进循环

```yaml
每轮循环:
  1. 分析: 解析守卫命令输出，定位改进点
  2. 改进: 执行最小改动修复/优化（遵循保守修改原则）
  3. 验证: 重新执行守卫命令 → 获取新指标值
  4. 判定:
     达标 → 输出: 确认（保留改进 / 回到基线）→ ⛔ END_TURN
     未达标但有进步 → 继续下一轮
     未达标且无进步（指标持平或退步）→ 回滚本轮 → 尝试不同策略
     连续2轮无进步 → 中止循环 → 步骤5

  轮次记录: 每轮记录（改动摘要、指标变化、耗时）

回滚机制:
  每轮改进前创建 git stash 或备份
  回滚 = 恢复到上一轮结束状态
  用户可选择回滚到任意历史轮次
```

### 步骤5: 循环结束

```yaml
结束条件（满足任一）:
  - 指标达标
  - 达到最大轮次
  - 连续2轮无进步
  - 用户中止

输出: 确认（循环结果）
⛔ END_TURN

用户选择:
  保留全部改进: 保持当前状态
  保留到第N轮: 回滚到第N轮结束状态
  全部回滚: 恢复到基线状态
  继续循环: 重置轮次计数，继续改进（仅限用户中止或轮次耗尽时）

输出: 完成（最终指标值 + 改进历史 + 保留/回滚结果）
→ 状态重置
```

---

## 不确定性处理

| 场景 | 处理 |
|------|------|
| 守卫命令执行失败 | 检查命令正确性，提示用户修正 |
| 指标无法自动解析 | 输出原始结果，请用户判断是否达标 |
| 改进引入新问题 | 回滚本轮，记录冲突，尝试替代策略 |
| 基线已达标 | 直接完成，提示无需改进 |

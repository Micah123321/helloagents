# ~prd 命令 - 产品需求文档

本模块定义通过逐维度讨论生成结构化产品需求文档（PRD）的规则。

---

## 命令说明

```yaml
命令: ~prd [<产品/功能描述>]
类型: 完整流程类
功能: 通过逐维度讨论生成现代产品需求文档
目标模式: INTERACTIVE（默认），可切换 DELEGATED
```

**DO:** 逐维度与用户讨论，确保每个维度信息充分后再进入下一维度

**DO NOT:** 一次性输出完整 PRD 而跳过讨论过程，在用户未确认维度内容前继续下一维度

---

## 执行模式适配

```yaml
规则:
  1. 默认 INTERACTIVE 模式，逐维度与用户讨论
  2. DELEGATED 模式下自动选择推荐选项，快速生成
  3. PRD 文档写入 {KB_ROOT}/plan/ 或用户指定路径
  4. 不创建方案包（tasks.md），仅输出 PRD 文档
```

---

## 执行流程

### 步骤1: 需求理解 + EHRB 检测

```yaml
按 G4 R2 标准流程执行需求评估:
  评分 + 追问（按 EVAL_MODE）+ EHRB 检测
  确认后设置 WORKFLOW_MODE

无描述: 输出: 错误（请提供产品/功能描述），流程结束
```

### 步骤2: 上下文收集

```yaml
已有项目: 读取项目上下文（知识库/代码库/配置），识别技术栈和约束
全新产品: 收集目标用户、市场定位、竞品信息

外部搜索（按需）: 竞品分析、行业趋势、技术可行性
```

### 步骤3: 逐维度讨论

```yaml
PRD 维度（按顺序讨论，每个维度一个回合）:

  维度1 - 产品概述:
    内容: 产品愿景、目标用户、核心价值主张、成功指标
    讨论: 输出初稿 + 2~3 个关键问题 → ⛔ END_TURN
    用户回复后: 更新该维度内容 → 进入维度2

  维度2 - 功能范围:
    内容: 核心功能列表、优先级矩阵（Must/Should/Could/Won't）、MVP 范围
    讨论: 基于维度1推导功能清单 + 询问优先级 → ⛔ END_TURN
    用户回复后: 更新该维度内容 → 进入维度3

  维度3 - 用户场景:
    内容: 核心用户故事、用户旅程、关键交互流程
    讨论: 为每个核心功能编写用户故事 + 询问边界场景 → ⛔ END_TURN
    用户回复后: 更新该维度内容 → 进入维度4

  维度4 - 技术约束:
    内容: 技术栈选型、性能要求、安全要求、集成需求、部署环境
    讨论: 基于项目上下文推荐 + 询问硬性约束 → ⛔ END_TURN
    用户回复后: 更新该维度内容 → 进入维度5

  维度5 - 验收标准:
    内容: 功能验收条件、性能基线、质量标准、发布条件
    讨论: 基于前4个维度推导可测试条件 + 询问补充 → ⛔ END_TURN
    用户回复后: 更新该维度内容 → 进入步骤4

DELEGATED 模式:
  跳过逐维度讨论，AI 基于已有信息和推荐选项自动填充所有维度
  仅在信息严重不足时中断询问
```

### 步骤4: 生成 PRD 文档

```yaml
整合5个维度内容，生成结构化 PRD 文档:

文档结构:
  # PRD: {产品/功能名称}
  ## 元信息（日期、版本、作者、状态）
  ## 1. 产品概述（愿景、目标用户、价值主张、成功指标）
  ## 2. 功能范围（功能列表、优先级矩阵、MVP 范围、排除项）
  ## 3. 用户场景（用户故事、用户旅程、关键流程）
  ## 4. 技术约束（技术栈、性能、安全、集成、部署）
  ## 5. 验收标准（功能验收、性能基线、质量标准）
  ## 6. 里程碑（可选，用户要求时填充）
  ## 附录（术语表、参考资料）

写入路径: {KB_ROOT}/plan/PRD_{feature}.md 或用户指定路径

输出: 确认（PRD 预览摘要）
⛔ END_TURN
用户确认后:
  确认: 写入文件 → 步骤5
  修改: 指出修改点 → 更新后重新确认
  取消: → 状态重置
```

### 步骤5: 后续操作

```yaml
输出内容:
  PRD 文档路径
  关键指标摘要（功能数、用户故事数、验收标准数）
  后续建议（~plan 生成实施方案 或 ~auto 直接实现）

输出: 完成（PRD 已生成）
→ 状态重置
```

---

## 不确定性处理

| 场景 | 处理 |
|------|------|
| 产品描述过于模糊 | 维度1讨论时重点澄清 |
| 用户跳过某维度 | 标注"待补充"，不阻塞后续维度 |
| 技术选型无法确定 | 列出候选方案，标注待定 |
| PRD 与现有方案包冲突 | 提示用户选择更新现有方案或独立保存 |

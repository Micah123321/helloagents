# 领域编码检查清单

本模块收拢散落在 G1（编码原则）、G8（UI 基线）、develop.md 中的领域编码规范，
按"安全 / 测试 / 架构 / 错误处理 / 性能"五域聚合为可勾选的验收清单。

加载时机: DEVELOP 步骤6-9（编码与验证阶段）按 G7 按需读取表"DEVELOP 按需"行加载；
按当前任务涉及的域选择性勾选，非全量强制。

本文件是现有规范的索引与提醒层，不新增规则、不覆盖 G1/G8/develop.md 的具体定义。
冲突时以 G1/G8/develop.md 为准。

---

## 使用方式

```yaml
- 编码阶段: 对照本次变更涉及的域，逐项自检对应清单
- 完成阶段: 未勾选项必须说明原因（不适用 / 已在别处验证 / 待修复）
- 非全量: 未涉及的域整域跳过（如纯后端任务跳过 UI 域的视觉项）
- 标记: 验收报告中用 [√] 通过 / [-] 不适用（附原因） / [X] 未通过（需修复）
```

## 安全域（涉及认证/密钥/权限/外部输入时）

```yaml
检查清单:
  - [ ] 无硬编码密钥/密码/token（环境变量或密钥管理服务）
  - [ ] 所有外部输入（用户/API/文件）已验证，白名单优先于黑名单
  - [ ] SQL 使用参数化查询，未拼接字符串
  - [ ] 敏感数据不在日志/错误信息/响应中暴露（脱敏后再记录）
  - [ ] 认证 token 有过期时间，JWT payload 不含敏感数据
  - [ ] 权限检查覆盖资源所有权（不只检查角色）
  - [ ] 文件上传验证类型/大小/内容，不信任扩展名
参考: G2 EHRB 检测三层规则
```

---

## 测试域（编写/修改测试时）

```yaml
检查清单:
  - [ ] 测试覆盖公共接口和外部可观察行为，不锁定实现细节
  - [ ] 核心业务逻辑有单元测试
  - [ ] 测试名描述行为（should reject expired tokens），非 test token
  - [ ] 覆盖边界用例（空值 / 0 / -1 / MAX / 超长字符串 / 错误路径）
  - [ ] 每个测试独立，不依赖执行顺序
  - [ ] Mock 外部依赖，不 mock 被测代码本身
  - [ ] 断言具体值，不只断言"不为空"
  - [ ] Bug 修复先写失败测试复现，再修复
参考: develop.md 步骤8 测试执行与验证
```

---

## 架构域（重构/调整模块结构/管理依赖时）

```yaml
检查清单:
  - [ ] 无循环依赖（循环依赖 = 架构问题，必须解决）
  - [ ] 文件/类不超过 400 行，函数不超过 60 行（例外类型除外，非压缩代码）
  - [ ] 依赖方向正确（外 → 内: UI → Service → Repository）
  - [ ] 按功能分组（feature-based），非按类型分组
  - [ ] 三次重复才提取（两次相似不够，避免过早抽象）
  - [ ] 变更影响范围（blast radius）已评估，大重构分步可独立回滚
  - [ ] 区分真实外部契约与内部实现惯性，不保留旧兼容层（除非真实契约要求）
参考: G1 代码体积控制、最小化阶梯、过度工程禁止规则
```

---

## 错误处理域（实现 try-catch/日志/重试/降级时）

```yaml
检查清单:
  - [ ] 区分可预期错误（正常处理，友好信息）与不可预期错误（记日志，通用错误）
  - [ ] 不用 try-catch 包裹所有代码，只捕获能处理的
  - [ ] 错误响应格式统一（{ code, message, details? }），HTTP 状态码准确
  - [ ] 不暴露内部实现细节（堆栈/SQL/文件路径）给用户
  - [ ] 结构化日志含 timestamp/level/context，错误日志含堆栈和请求 ID
  - [ ] 外部调用有超时设置 + 重试（指数退避，最多 3 次）
  - [ ] 无静默失败: 无空 catch 吞错误、无静默降级、无静默回退 [→ G2 静默失败防护]
参考: G2 静默失败防护
```

---

## 性能域（优化查询/缓存/算法/资源时）

```yaml
检查清单:
  - [ ] 无循环内的重复计算或低效查询（N+1 查询、循环内 I/O）
  - [ ] 大数据集使用分页/虚拟滚动/聚合，不一次性全量加载
  - [ ] 可缓存结果已识别缓存策略（缓存粒度、失效时机）
  - [ ] 资源（连接/文件句柄/锁）已正确释放（含异常路径）
  - [ ] 算法复杂度匹配数据规模（无 O(n²) 用于大集合，除非有 ha-min 标注的上限）
  - [ ] 并发场景已考虑竞态（如适用）
参考: G1 ha-min 标注规则（已知上限的快捷方案须标注升级路径）
```
